## 背景与动机

`南京南站附近1`（33 张）有 5 张 iPhone 锚点（落在 2 处、相距 114 m）、28 张 SONY NEX-5N 照片缺坐标。现有能力下：

- 交互模式逐张 `y/n`，28 轮"看图 + 按键"，用户明确反馈低效；
- `--all` 一次只支持一个参照，两组锚点覆盖不了，且需跑 28 条逐张命令；
- `npm run photos` 预检只在"恰有 1 张锚点"时给批量命令，多锚点时用户不知道下一步。

归属的本质是**分组决策**而非逐张决策：相机照集中在 5 分钟内连拍，锚点只在两个时刻。审阅页把决策压缩为"看一页 + 调分界 + 确认一次"。

## 设计

### 1. fix-gps.js 新增 `--review`：生成分组审阅页

用法：`npm run fix-gps -- "南京南站附近1" --review`

- 扫描该文件夹（口径与现有一致：跳过 `_thumb` / `_display`），exifr 读 `GPSLatitude` / `GPSLongitude` / `DateTimeOriginal` / `GPSProcessingMethod`。
- 生成单文件 HTML 到临时目录（`os.tmpdir()/hcm-fix-gps-review/<文件夹名>.html`），随后 `open`（macOS）打开。页面**只读**，不写任何照片。
- 缩略图用**既有派生图** `_thumb`（`npm run photos` 已生成），`<img src="file:///绝对路径">` 引用，不做 base64 内联；某张缺 `_thumb` 时降级显示文件名占位块，不报错中止。
- 页面结构 = 原型定稿的 5 个区块：① 密度条 + 胶片条（D 形态核心）② 分组审阅（锚点卡 + 全部改投 + 分界滑杆）③ 按时间照片网格（存疑筛）④ 计划 JSON 预览 + 复制 ⑤ 锚点相对位置示意。交互（点图并排对照、`←/→` 翻页、徽章改投、Esc）与原型一致。
- **GPS 三态徽章**（用户确认的需求）：
  - 锚点-原生（无 `hcm-geosource` 标记）：绿 📍 + 实色粗边框；
  - 锚点-复制（`GPSProcessingMethod` 含 `hcm-geosource`，即早前从参照复制的坐标）：灰绿 📍 徽章，区分坐标来源——对应 `docs/photo-metadata.md` 的坐标溯源契约；
  - 待补（无 GPS）：虚线边框 + `→ 锚点X · 时间差` 徽章，>60 秒带存疑点。
- 默认分组 = 按拍摄时间就近；两组以上锚点时"分界滑杆"退化为分组卡上的改投按钮（滑杆仅两锚点时出现，与原型一致）。
- 导出桥：页面「复制计划 JSON」→ 用户终端跑 `pbpaste | npm run fix-gps -- "<文件夹>" --plan-stdin`；同时也支持落盘文件后 `--plan <file>`。

### 2. fix-gps.js 新增 `--plan <file>` / `--plan-stdin`：读计划一次写入

计划 JSON 结构（与原型第 ④ 区块一致）：

```json
{ "dir": "南京南站附近1", "groups": [ { "ref": "IMG_5815.JPG", "lat": 31.971153, "lng": 118.789611, "targets": ["DSC04901.JPG", "..."] } ] }
```

校验链（任一失败即报错退出 1，**零写入**）：

- `dir` 与位置参数一致；`groups` 非空；`targets` 非空且文件都存在；
- 每个 `ref` 存在、有 GPS，且**实际 EXIF 坐标与 JSON 内 lat/lng 偏差 < 1e-4 度**（防计划过期/被手改）；
- 每个 `target` 当前确实缺 GPS（已有坐标的自动跳过并打印，天然幂等续作）。

写入复用 `writeGps()`：溯源标记 `hcm-geosource ref=<参照> date=<日期>`、不复制 GPSHPositioningError、写入后验证（COORD_EPSILON）全部继承。流程：打印分组摘要（锚点 / 张数 / 时间范围）→ 终端按一次 `y` 确认 → 批量写入；任一张验证失败即停止后续写入、退出码 1。`--yes` 与 `--plan` 叠加时跳过确认键（保持既有 `--yes` 语义）。

### 3. process-photos.js 预检提示增强

`preflightDir()` 缺坐标分支：

- 锚点 = 1 张：维持现状（交互 + `--all` 两行提示）；
- 锚点 ≥ 2 张：hint 扩为两行——交互命令 + 审阅页命令（`npm run fix-gps -- "<文件夹>" --review`），并附一行锚点摘要（如 `5 张锚点落在 2 处，相距 114 m`）；
- 锚点 = 0 张：维持现状。

同步更新 `printUsage()` 与文件头注释。

### 4. 文件与知识回写

- 新文件：`fix-gps-review-template.html`（repo 根目录，与 fix-gps.js 同级；模板内嵌 CSS/JS，`__DATA__` 占位符注入扫描结果）。
- `docs/photo-workflow.md`：补"多锚点文件夹标准路径 = `--review` → 复制 JSON → `--plan-stdin`"一段。
- `docs/photo-metadata.md`：补三态徽章与 `GPSProcessingMethod` 溯源标记的对应关系；**补 `--ref` 大小写敏感精确匹配的坑**（本会话实测：`IMG_5815.jpg` 匹配不到 `IMG_5815.JPG`）。
- AGENTS.md 路由不动（知识进既有域文件）。

## 验收标准

1. `npm run fix-gps -- "南京南站附近1" --review` 生成审阅页并自动打开；页面 33 张全出现、5 锚点带 📍、28 张虚线框预设时间就近归属；密度条高峰对应 14:29 连拍簇；点密度条柱能跳到胶片条对应卡。
2. 页面导出的 JSON 经 `--plan-stdin` 写入后：28 张全部获得坐标且验证通过，geoSource 标记指向各自锚点；重跑 `npm run photos` 该文件夹不再被跳过。**此步交用户终端执行（S1）**，agent 验证仅到"校验链拒绝非法计划 + 零写入"为止，可在临时目录的副本上做（S1 允许）。
3. 计划校验：ref 坐标被篡改 / target 不存在 / groups 为空 → 报错退出 1、零写入。
4. `npm run photos` 对该文件夹的预检提示出现 `--review` 命令与锚点摘要行；单锚点与零锚点文件夹提示不变。
5. `npx eslint fix-gps.js process-photos.js --max-warnings=0` 通过（repo 根目录脚本，不在 src）。
6. 无 `--review` / `--plan` 时 fix-gps 既有交互模式与 `--all` 行为零变化。

## 出界清单（本计划明确不做）

- 方案 4 地图视图（AMap 底图 + 拾取坐标）：需 key + 联网，与 file:// 离线架构冲突，锚点仅 2 处时收益不成比例；密度条/胶片条形态已覆盖当前需求。
- 页面内直接写照片（本地 server 或浏览器写文件）：页面保持纯只读，写入永远经终端确认（P2 门②）。
- 自动写入（无确认键）：`--plan` 仍保留一次 `y`。
- 时间聚类阈值自动归属（原方案 3 单独落地）：时间就近默认分组已覆盖，阈值概念保留为"存疑"角标。
- `_thumb` 缺失时的现场补图：降级占位即可，补图属 photos 管线职责。
  ⚠️ 实际实现偏离了本条——`resolveThumbSrc()` 对"HEIC 且无派生缩略图"做了 sips
  转临时 JPEG 兜底（否则 HEIC 锚点卡在页面上是空块）。偏离已记在上方"实现说明"，
  此处补注以消除文档内自相矛盾。
- 跨文件夹审阅 / 多文件夹批量。

## 实现后修订（2026-10-04，均经用户当次批准）

原始设计在多轮实测与用户反馈后有几处偏离，按 P1 保留记录：

1. **导出桥从 `pbpaste` 改为单行命令**（用户提出，优于 agent 给的四个方案）：页面复制
   按钮产出 `echo '<单行 JSON>' | npm run fix-gps -- "<文件夹>" --plan-stdin`，数据与
   命令合并为同一次剪贴板写入——根治"剪贴板单槽竞争"（复制 JSON 后再复制命令文本会
   覆盖它）。JSON 必须压缩单行（换行会被终端当回车提前执行），单引号转义 `'\''`。
2. **`--plan-stdin` 收尾挂起 bug 及修复**（用户报告）：非 TTY 分支原用
   `readline.createInterface({input: fs.createReadStream('/dev/tty')})`，该流会在
   /dev/tty 上留一个挂着的读请求，`rl.close()` / `stream.destroy()` 都取消不掉 →
   汇总打印后事件循环不 drain、进程不退出。改为同步阻塞读（`openSync` + `readSync`
   + `closeSync`），实测 0.7s 正常退出。坑的通用描述见 `docs/toolchain.md`。
   **否决的替代方案**：废掉 `--plan-stdin` 改走临时文件（用户明确偏好"复制命令→
   执行→看结果"的无落盘流程）；`terminal: false`、`stdin.pause()+unref()`、
   `destroy()` 三种尝试实测均无效（已排除，勿重试）。
3. **归属规则：并列时取较后拍摄的锚点**（用户设计目标，agent 给等价的零代价实现）：
   同秒并列必然同地，选谁写入结果一致，取后拍者只为让时间轴色块连续。否决了毫秒精度
   （跨设备时钟漂移是秒级，0.556s 差异是噪声，且要动 fix-gps.js）与文件名排序
   （IMG/DSC 跨厂商编号不可比、编号回卷、重命名失效）。
4. **视觉编码收敛为"一个维度一个通道"**（用户质疑绿色徽章后）：颜色只表示归属组，
   `📍`/`📋`/`→` 图标表示坐标身份（原生 / 复制 / 待补），实虚边框表示有无坐标。
   原独立"状态绿"与组色撞近色，已全部清除。
5. **新增控件与自解释化**：悬停照片高亮密度条对应柱；「? 使用说明」帮助面板 + 全控件
   悬停提示；对照弹窗内一排锚点按钮 + 键盘 `A`–`E` 直选改投（替代"改用下一个锚点"
   的循环按钮）；"存疑"改为自解释徽章（永远显示真实时间差，>60 秒加 ⚠）。
6. **修复审阅页首个实测 bug**：`.overlay { display:flex }` 覆盖 `hidden` 的浏览器默认
   隐藏 → 弹窗从加载起常显并盖住全页；补 `.overlay[hidden] { display:none }`。
