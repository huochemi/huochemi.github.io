状态：已实现（2026-10-03）
实现说明：按设计落地；`--all` 的参照校验复用手动指定模式同款错误分支；沙箱内完成
参数校验与只读链路验证（exiftool 预检前/后的错误路径），写入验证按 S1 交用户终端执行。
日期：2026-10-03
来源会话：用户提出"同一地点连拍大量照片，逐张确认太重复"；经 A（批量确认键）/ B（时间聚类）/ C（CLI 批量）对比后，用户选定"photos 提示 + 一条批量命令"的组合。

## 背景与动机

`npm run photos` 预检发现文件夹缺坐标时（如 `南京南站附近1：28/29 张缺坐标`），目前只提示交互式修复 `npm run fix-gps -- "文件夹"`。当整个文件夹实际是同一地点时，逐张预览确认是重复劳动。目标：提供一条命令，把**指定的参照照片**坐标一次性写入该文件夹**所有缺 GPS 的照片**，并在 photos 预检失败提示里直接给出这条命令（含参照文件名），实现"跑 photos → 复制粘贴一条命令 → 重跑 photos"的最短路径。

## 设计

### 1. fix-gps.js 新增 `--all` 参数（批量模式）

用法：

```
npm run fix-gps -- "南京南站附近1" --ref DSC04375.JPG --all
```

语义：将 `--ref` 指定照片的坐标写入该文件夹内**所有缺 GPS 的照片**（参照本身有 GPS，天然不在目标列表）。

规则：

- `--all` 必须与 `--ref` 和位置参数（文件夹名）同时使用，缺任一即报错退出并打印用法（不做"自动选参照"——参照由用户/photos 提示明确指定，零猜测）。
- 复用既有校验链：文件夹存在、`--ref` 存在且有 GPS（复用 main() 中手动指定模式的校验逻辑）。
- 写入复用 `writeGps()`：溯源标记 `hcm-geosource ref=... date=...`、不复制 GPSHPositioningError、写入后验证（偏差 > COORD_EPSILON 即失败）全部继承，契约不变。
- **非交互**：无预览、无按键。命令本身就是用户的确认（与 `--yes` 的定位一致）。
- 逐张打印 `✓ 已写入并验证：<文件名>`；任一张写入后验证失败 → 立即停止全部后续写入并退出码 1（与现有 run() 行为一致），已写入的保持已写入（重跑 `--all` 会自动跳过它们，因为已有 GPS 不再进目标列表——天然幂等续作）。
- 目标列表为空（无缺 GPS 照片）→ 打印"没有缺 GPS 的照片"正常退出。
- 结束打印汇总（写入 N 张 / 0 张跳过）与下一步提示（`npm run photos` 重新生成数据），复用 `printSummary()`。
- 同步更新文件头注释与 `printUsage()`。

### 2. process-photos.js 预检失败提示增强

`preflightDir()` 缺坐标分支（现第 468-474 行）：

- 计算 `refs = images 中有坐标且文件名不含 _display 的照片`（排除 _display 与 fix-gps 的扫描口径对齐；_thumb 本就被 imageFiles 过滤）。
- `refs.length === 1` 时，hint 扩为两行（hint 变量含 `\n`，reportSkippedDirs 的打印模板不变）：

  ```
  补坐标后重跑：npm run fix-gps -- "文件夹"
  或批量复制坐标（将 <ref文件名> 的坐标写入其余 N 张）：
    npm run fix-gps -- "文件夹" --ref <ref文件名> --all
  ```

- `refs.length` 为 0 或 ≥2 时维持现状（只提示交互命令）——0 张无法批量；≥2 张时参照选择是用户的判断，不替用户拍板。

## 验收标准

1. `npm run fix-gps -- "<文件夹>" --ref <参照> --all` 将参照坐标写入该文件夹全部缺 GPS 照片，geoSource 标记指向该参照，逐张验证通过；期间任一张验证失败则停止后续写入、退出码 1。
2. `--all` 缺 `--ref` 或缺文件夹位置参数 → 报错 + 用法，退出码 1，不发生任何写入。
3. `npm run photos` 在缺坐标且恰有 1 张带坐标照片时，hint 同时给出交互命令与含参照文件名的批量命令；0 或 ≥2 张带坐标时提示与现状相同。
4. 既有交互模式（无 `--all`）行为零变化。
5. `./node_modules/.bin/eslint src --ext .js,.jsx,.ts,.tsx --max-warnings=0` 通过（注：fix-gps.js / process-photos.js 在 repo 根目录，不在 src，故另跑 `npx eslint fix-gps.js process-photos.js --max-warnings=0`）。
6. **写入验证交用户执行**（S1 数据隔离）：agent 不对 `../data/photos` 原始照片做任何写入测试；功能验证命令由用户在自己的终端跑（可直接对南京南站附近1 执行，或先复制文件夹到临时目录验证——由用户决定）。

- 时间聚类 / 组预览（方案 B）。
